What media-tube is

media-tube is a self-hosted library for a large video and photo collection, a private, multi-user alternative to handing your media to a cloud service. It is a Python application split into a server-rendered web dashboard and a separate HTTP API, with a custom player, keyword and semantic search, and a background-job system for the slow work. The AI layer is what makes it more than a file browser: automatic tagging from a vision model, Whisper transcription and translation, face and actor recognition, and embedding-based similarity, each with a human-in-the-loop review queue so the automation stays trustworthy. The survey below breaks down what that codebase's test suite actually covers.

What the media-tube suite actually watches

Data as of 2026-08-27. The migration the last survey set out, pulling business logic out of the web/presentation layer (dashboard/*) into the API where it is unit-testable, has largely landed: the api/media_tube_api package is now built out and tested, and overall coverage moved from 62% to 79%. The remaining gaps are concentrated in the web dispatch layer and a few dashboard orchestration modules.

79% of 13,235 statements, measured from a real run, not carried forward from a stale number. A one-line coverage percentage says nothing about which 21% is missing; this is that breakdown, module by module, with what is worth doing about it.

Findings

services/web/app.py56%

Still the single largest gap by raw uncovered lines. app.py is the HTTP dispatch table, the layer that decides which function answers which route. Every other module's logic is unit-tested by calling its functions directly, which proves the logic works but not that each route is wired to it correctly. It has climbed from 48% as more endpoints route through the real client fixture; the remaining lines are endpoints still tested by calling their handler directly. Fixed the same way: route each through conftest's app_server / client fixtures, which already exist.
