What media-tube is

media-tube is a self-hosted library for a large video and photo collection, a private, multi-user alternative to handing your media to a cloud service. It is a Python application split into a server-rendered web dashboard and a separate HTTP API, with a custom player, keyword and semantic search, and a background-job system for the slow work. The AI layer is what makes it more than a file browser: automatic tagging from a vision model, Whisper transcription and translation, face and actor recognition, and embedding-based similarity, each with a human-in-the-loop review queue so the automation stays trustworthy. The survey below breaks down what that codebase's test suite actually covers.

Findings

services/web/app.py48%

This is the one gap the suite has already proven costs something. app.py is the HTTP dispatch table, the layer that decides which function answers which route. Every other module's logic is unit-tested by calling its functions directly, which is real coverage of the logic but proves nothing about whether a route is wired to it correctly. Fixed the same way it is elsewhere: conftest's app_server / client fixtures already exist and serve the real Handler, used for photos and search today. Routing every new endpoint through client.get() instead of calling its handler directly is the whole fix; no new infrastructure needed.

Already accounted for

web/dashboard/faces.py57%

Four sub-areas are named in the README as genuinely untestable: recognition quality and real ffmpeg decoding are properties of a model and a codec, not this code. Everything else in the file is testable and simply deferred, tracked by the owner as its own workstream.

Reads as one gap; it is two. The 43% split between can't-test and haven't-yet is not visible from the number alone.
web/dashboard/autotag_eval.py42%

Model-quality assertions are excluded by design: asserting which tags a vision model returns tests the model, not this code. Resolution, prompting, JSON repair and scoring are unit tested.

Re-verifying the documented exclusions still match the code.
web/dashboard/previews.py37%

Whether a hover clip looks good is a perceptual judgement excluded on purpose. Source selection, safe paths and command construction are covered.

Same re-verification as autotag_eval.py, confirming the perceptual exclusions are as narrow as documented.
web/dashboard/embeddings.py58%

Semantic search's move onto the api is explicitly deferred to a v2 search plan (IDEAS.md): this module is mid-migration, not neglected.

Deferred with a written plan, not an oversight.
